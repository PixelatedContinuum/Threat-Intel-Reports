{%- comment -%} T-0532 part S: one Wire row as one Details fact-sheet entry. Called from wire/details-nkev.json (the lead "added") and wire/details-cves.json (the lead "published") with r = one row that the calling page has already passed through its own shape guard. Every field the fact sheet reads is emitted, so one include is the schema for both tabs; a field the row does not carry or carries empty emits as an empty value (null or ""), exactly what the brief asks, and the renderer shows that section's line about absence. Every data value is emitted through | jsonify (the JSON pages' escaping rule, hard rule 1): a value holding a quote, a backslash or a control character cannot change the JSON shape. The key is the row's CVE lowercased, exactly the id the page puts on the row element, so the renderer finds its row by string id. One object per row, single line; the calling page owns "generated_at", the "rows" wrapper and the commas between rows. Every key after the first carries its comma at its FRONT, so no absence anywhere can leave a trailing comma. The one field shaped as a number that must NOT be coerced when empty is `gap`: a gap of "" coerced to 0 would claim "NVD published it the same day VulnCheck added it", so it is skipped when empty, and
